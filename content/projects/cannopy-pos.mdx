## 📱 Overview

**Cannopy POS** is a point-of-sale app for grocery stores, mini-marts, wholesalers and other small shops in Myanmar, made by **Cannopy Technologies**. It runs on the phones and tablets shops already have, and it's built around two facts of selling in Myanmar: the internet goes down, and money is often owed rather than paid.

So the till never waits for the network. Sales, stock, receipts, refunds, shifts and customer credit all live in a local database, and the app syncs with the cloud when it can. If several tills in one shop lose the internet together, they can still pass data between them over the shop's Wi-Fi. Receipts print on Bluetooth and network thermal printers, in Myanmar script.

It's a production app on Google Play and the App Store. I work on it in a small team, and I'm the largest contributor to the mobile codebase.

## ✨ Features

### 🛒 Selling

- Product grid by category, search and barcode lookup (camera or a Bluetooth scanner)
- Cart with item and invoice discounts, taxes and rounding rules
- Cash, digital and split payments, with change suggestions
- **Loose items** sold by weight or measure
- Held and draft orders that can be picked up later
- A **customer display** on a second screen showing the cart and total

### 🧾 Receipts and refunds

- Receipts stored on the device, reprinted at any time
- Full and partial refunds with PIN approval, which put stock back and record the cash payout. The original receipt never changes
- Receipt layout and design settings with a live preview

### 💳 Credit (A Kyway)

- When a customer pays less than the total, the shortfall is recorded as debt against them
- Repayments go to the oldest debt first and print their own receipt
- Customer statements

### 📦 Stock and catalogue

- Products with variants, bundles and kits, units, categories and taxes
- Pack and unpack between pack sizes and single units
- Stock adjustments, stock movement and stock reports
- Purchases from suppliers, supplier credit payments, and transfers between stores
- Price history, favourites and bulk import

### 👥 Staff, shifts and security

- Phone OTP sign-in for staff, then a PIN to unlock the till
- Shift in and shift out with cash drawer pay-in and pay-out, or a lighter "cashier session" mode for shops that don't run shifts
- The till locks itself after a set time without use
- Role-based permissions from the server, checked before each guarded action

### 🌐 Online and reports

- **Online orders** with a shop QR code customers scan to order
- Sales summaries, best sellers and tax reports
- Data export

## 🧠 Engineering Highlights

### The local database is the source of truth

Every screen reads from Drift, and every change is written there first, so checkout works the same with or without a connection. The schema is at **version 48**, and every change ships with a migration that keeps a shop's sales history intact. After sign-in, the app downloads a full snapshot of the shop's catalogue and settings. From then on it only pulls changes.

### Sync that can retry safely

Local changes go into an outbox. Each event's key is built from the store, event type, record, operation, time and a **SHA-256 fingerprint of the payload**, taken from a canonical form of the JSON. Retrying the same change sends the same key, so the server can drop duplicates. A real edit always gets a new key, so it's never mistaken for one already sent.

Each cycle pushes the outbox first, then pulls the cloud's changes since the last **cursor**. Pulled changes are staged, applied, and only then **acknowledged**, so the cursor moves forward only for changes that are safely stored. Shop data and shared reference data each have their own cursor. Sync runs only while the app is in use, and polling needs a server request each time, so an **MQTT** connection carries "something changed" hints that trigger a pull straight away. Because MQTT can drop messages while offline, the app refetches when it reconnects instead of trusting it fully.

### Tills that talk to each other offline

In a shop with several tills and no internet, one till hosts and the others connect over the local network. The `app_local_network` package covers:
- **mDNS discovery** (with a native multicast lock on Android)
- TCP messaging with **chunking** for large tables
- a shared-secret session, rate limiting, heartbeats and automatic reconnects
- a UDP fallback for networks where discovery doesn't work

### Printing Myanmar on cheap thermal printers

Most receipt printers can't draw Myanmar script. A Kotlin plugin draws each Myanmar line onto a bitmap with the app's font, then turns the bitmap into ESC/POS raster commands, so receipts print correctly on any ESC/POS printer. Other native plugins find Bluetooth printers, read Bluetooth HID barcode scanners, and drive the customer-facing display through Android's Presentation API.

### Money rules written down, then coded

Discounts, invoice discounts, tax, rounding, loose items, credit shortfalls, repayments and refunds each have a written rule document in the repo, and the code follows it. Repayments are allocated oldest debt first, refunds can never touch the original receipt, and approved or rejected refunds are final.
